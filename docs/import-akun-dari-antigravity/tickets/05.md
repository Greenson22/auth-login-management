# 05: Penanganan duplikat email + Simpan ke DB

**What to build:** Alur simpan lengkap: sebelum form tampil, sistem mendeteksi apakah email yang diimport sudah ada di database. Jika ya, banner peringatan muncul dengan nama akun lama dan pengguna harus memilih tindakan (Perbarui Token atau Tambah Baru) sebelum tombol Simpan aktif. Setelah simpan berhasil, tabel akun di main window diperbarui otomatis.

**Blocked by:** 04

**Status:** ready-for-agent

- [ ] Saat `ImportDialog` dibuka, sistem mengecek apakah email (case-insensitive) sudah ada di database via `AccountDatabase`.
- [ ] Jika email belum ada: form tampil normal, tombol "Simpan" langsung aktif.
- [ ] Jika email sudah ada: banner peringatan kuning muncul di atas form yang menampilkan ID dan email akun yang sudah ada di DB.
- [ ] Saat duplikat terdeteksi: dua pilihan ditampilkan (radio button): **"Perbarui Token"** dan **"Tambah sebagai Entri Baru"**.
- [ ] Tombol "Simpan" dinonaktifkan selama belum ada pilihan tindakan yang dipilih (saat duplikat).
- [ ] Tombol "Simpan" aktif kembali setelah pengguna memilih salah satu tindakan.
- [ ] Tindakan **Perbarui Token**: memanggil `update_refresh_token()` pada akun yang sudah ada; jika kuota tersedia di form, memanggil `update_account_quotas()` juga.
- [ ] Tindakan **Tambah sebagai Entri Baru**: memanggil `insert_or_update_json()` dengan ID baru; jika kuota tersedia, disimpan bersama entri baru.
- [ ] Enkripsi menggunakan password sesi aktif yang dilewatkan ke dialog — tidak ada prompt password tambahan.
- [ ] Setelah simpan berhasil: dialog ditutup dengan status `Accepted`; `MainWindow` memanggil `reload_accounts()`.
- [ ] Tombol "Batal" menutup dialog tanpa perubahan DB apapun.
- [ ] Test widget mencakup semua 7 kasus yang didefinisikan di SPEC: insert baru, perbarui token, tambah baru (duplikat), token tidak valid tapi simpan tetap jalan, kuota gagal tapi simpan tetap jalan, batal tanpa perubahan DB, tombol Simpan disabled sampai pilihan dipilih.
