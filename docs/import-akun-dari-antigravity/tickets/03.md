# 03: Validasi token async di ImportDialog

**What to build:** Saat `ImportDialog` dibuka, validasi refresh token berjalan otomatis di background tanpa membekukan UI. Hasilnya ditampilkan sebagai badge status di form (✅ Valid / ❌ Tidak Valid / ⚠️ Gagal koneksi). Jika Google telah merotasi token, field refresh token di form diperbarui otomatis dengan token baru dari respons OAuth. Pengguna tetap bisa mengisi/mengedit form selama validasi berlangsung.

**Blocked by:** 02

**Status:** completed

- [x] Validasi token dijalankan via `WorkerThread` yang sudah ada segera setelah dialog dibuka (bukan menunggu klik pengguna).
- [x] Selama validasi berlangsung: badge menampilkan "⏳ Memvalidasi…" (abu-abu); tombol "Simpan" tidak diblokir.
- [x] Jika token valid: badge "✅ Token Valid" (hijau).
- [x] Jika token tidak valid (`invalid_grant` atau error OAuth lain): badge "❌ Token Tidak Valid: `<kode error>`" (merah); form tetap bisa diisi dan disimpan (pengguna tetap berhak menyimpan token yang tidak valid).
- [x] Jika koneksi gagal (timeout/jaringan): badge "⚠️ Validasi gagal (timeout/jaringan)" (oranye).
- [x] Jika respons OAuth mengandung `refresh_token` baru (Google merotasi token): field refresh token di form diperbarui otomatis dengan nilai baru.
- [x] Refresh token tidak pernah muncul di teks badge, pesan error, atau log pada level apapun.
- [x] Test widget mencakup: token valid → badge ✅; token `invalid_grant` → badge ❌; field token diperbarui jika respons OAuth memuat token baru. Menggunakan `FakeOAuth.respond_for()` dan `FakeOAuth.fail_with()` yang sudah ada.
