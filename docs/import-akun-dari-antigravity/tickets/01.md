# 01: Foundation — Exception types + KeyringReader

**What to build:** Buat pondasi yang memungkinkan seluruh alur import membaca dan memparsing Keyring Item dengan aman. Setelah tiket ini selesai, ada modul `KeyringReader` yang bisa dipakai tiket berikutnya, lengkap dengan penanganan semua kondisi error (item tidak ada, keyring terkunci, keyring tidak tersedia, JSON rusak). Exception types yang selama ini hanya ada di modul test dipindah ke kode produksi.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] `KeyringItemNotFoundError` dan `KeyringParseError` tersedia di kode produksi (bukan hanya di modul test), sehingga bisa diimpor dari mana saja tanpa mengimpor modul test.
- [ ] `KeyringUnavailableError` dan `KeyringLockedError` juga tersedia di kode produksi (duplikat atau pindah dari `tests/fakes.py`).
- [ ] `KeyringReader.read_and_parse(keyring)` membaca item `service=gemini, username=antigravity` dan mengembalikan dataclass `KeyringImportData` dengan field: `refresh_token`, `email` (opsional, dari decode id_token JWT), `project_id` (opsional), `raw_fields` (seluruh field JSON lain).
- [ ] Jika item keyring tidak ada: raise `KeyringItemNotFoundError`.
- [ ] Jika keyring tidak tersedia (D-Bus error): raise `KeyringUnavailableError`.
- [ ] Jika keyring terkunci: raise `KeyringLockedError`.
- [ ] Jika JSON keyring tidak valid atau field wajib (`refresh_token`) tidak ada: raise `KeyringParseError`.
- [ ] Jika `id_token` tidak ada atau tidak bisa di-decode: `email` bernilai `None` (bukan error).
- [ ] File test `tests/test_keyring_reader.py` ditulis dan lulus untuk semua 6 kasus di atas, menggunakan `FakeKeyring` dan `make_id_token()` dari `tests/fakes.py` (tidak ada fake baru).
- [ ] Tidak ada `import dbus` langsung di modul `KeyringReader` — dependensi diinjeksi lewat `KeyringPort`.
